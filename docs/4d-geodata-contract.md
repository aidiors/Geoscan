# Контракт 4D-ограничений KML и GeoJSON

GeoPlan не пытается превращать произвольный текст вроде `Altitudes` в
операционное ограничение. Текст сохраняется как исходные метаданные, а в
расчёт попадают только явные числовые поля. Это исключает опасную догадку о
системе отсчёта, единицах и периоде действия.

## Поля

Для KML поля передаются в `ExtendedData/Data` или `SchemaData/SimpleData`, для
GeoJSON — в `Feature.properties`:

| Поле | Формат | Назначение |
|---|---|---|
| `minimum_altitude_m` | число | нижняя граница высотного слоя, м |
| `maximum_altitude_m` | число | верхняя граница высотного слоя, м |
| `altitude_reference` | `msl` или `agl` | система отсчёта числового диапазона |
| `valid_from` | ISO 8601 | начало действия с часовым поясом |
| `valid_to` | ISO 8601 | окончание действия с часовым поясом |
| `restriction_type` | `permanent`, `prohibited`, `special`, `temporary`, `unknown` | тип ограничения в GeoJSON |
| `validity` | объект GeoJSON | `{ "mode": "time_window", "valid_from": ..., "valid_to": ... }` |

В KML тип по-прежнему читается из исходного поля `Type`. Обе границы высоты
задаются вместе, верхняя должна быть выше нижней. Для числового диапазона
обязательно явное `altitude_reference`; вместо него KML может использовать
однозначный `altitudeMode=absolute` (MSL) или `relativeToGround` (AGL). Обе даты временного окна
задаются вместе, содержат часовой пояс и идут в хронологическом порядке.

Если высотный диапазон отсутствует, запретная зона консервативно относится ко
всем высотам. Если `temporary` не сопровождается корректным временным окном,
интерфейс не отправляет такой сценарий на оптимизацию и просит уточнить данные.

## Семантика планирования

- постоянная запретная зона строит пространственный объезд;
- временная запретная зона, пересекающая маршрут и эшелон, создаёт запрещённый
  интервал запуска, поэтому модуль расписания может дождаться её закрытия;
- разрешённые объёмы объединяются на каждом непрерывном временном интервале;
- вся миссия, включая неопределённость старта, должна помещаться в допустимое
  окно;
- `planning_end_time` задаёт конец рабочего или вручную рассчитанного светового
  окна; астрономический восход/закат автоматически пока не вычисляется.

AGL-миссия с DEM содержит одновременно профиль MSL и гарантированный клиренс
AGL. Поэтому ограничения обоих типов проверяются в собственной системе отсчёта
и повторно проходят независимый аудит безопасности. MSL-миссия с AGL-ограничением без
terrain-following профиля отклоняется: прямое сравнение этих величин запрещено.
Flight Level намеренно не принимается как метры; его можно загрузить только после
подтверждённого преобразования в MSL с сохранением источника и атмосферных условий.

Перед эксплуатацией импортированные ограничения всё равно требуют проверки по
официальному актуальному источнику. Поставляемый справочный KML не содержит
стандартных временных меток для временных зон и сам по себе не является
оперативным источником статуса воздушного пространства.


## Время движения в экспортируемом плане

В `Mission.stages` фаза может содержать `leg_durations_minutes`: массив
длительностей горизонтальных плеч в минутах между соседними `coordinates`.
Длина массива равна числу координат минус один. Значения конечны,
неотрицательны, положительны для перемещения в горизонтальной плоскости.
Новые штатные миссии сохраняют эти значения с учётом ветра и ограничения
скорости съёмки. Экспорт плана сохраняет метаданные фаз для последующей проверки.

Явный clock требует непрерывной последовательности всех подвижных фаз,
совпадающей с `Mission.route`, и суммы горизонтальных времён, согласованной
с длительностью миссии. Длительность каждой фазы также согласуется с
суммой её плеч и соответствующей вертикальной добавкой. Вертикальные добавки взлёта/снижения учитываются
отдельными полями миссии. Расписание и аудит используют эту же временную
развёртку; экспорт автопилота задаёт соответствующую путевую скорость
на плечах. Отдельные `SURVEY` дают отдельные полосы покрытия, без
добавления снятой полосы между ними.

Старые объекты без `leg_durations_minutes` принимаются. Если их фазовые
длительности и геометрия согласованы, используются фазовые времена;
при отсутствии согласованных данных сохраняется приближение равномерного
движения. Такой совместимый вход не восстанавливает неизвестный ветер
или неизвестные времена плеч. Округлять новые массивы вручную нельзя:
они должны оставаться согласованными с полной длительностью миссии.

## Явные точки фотосъёмки

У свободной миссии `photo_capture_route_indices` содержит возрастающие уникальные
индексы точек `route`, в которых запланирован снимок. `image_count` равен их
количеству; обязательны точные времена всех движущихся стадий. GeoJSON и KML
сохраняют список; QGroundControl и Mission Planner сохраняют одиночные команды
MAVLink 2000 с последовательными capture sequence ID. Дистанционный триггер
по усреднённому числу снимков в такой миссии не используется. Кадры проверяются
по аппаратному интервалу, включая короткие участки с выключенной камерой.
Поля добавлены в модель и OpenAPI; назначение прежних полей сохраняется.
