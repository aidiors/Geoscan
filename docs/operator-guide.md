# Руководство оператора GeoPlan

GeoPlan рассчитывает проект полётных заданий. Перед реальным вылетом оператор
должен проверить актуальность ограничений, комплектацию БВС, маршрут и экспорт
в используемом полётном ПО. Зелёный аудит в приложении подтверждает проверки
по введённым данным, а не разрешение на полёт.

## Подготовка сценария

1. Откройте приложение по адресу из [инструкции запуска](../README.md#запуск).
   В списке «Тестовый сценарий» можно выбрать готовый пример или настроить
   собственную область и парк.
2. Импортируйте рабочую область, запретные зоны, разрешённое пространство и
   препятствия из KML или GeoJSON. Перед выбором файла укажите тип слоя.
   Импортированные зоны перечисляются под загрузчиком и показываются на карте.
   Исходные KML из `reference/hackathon/` являются справочными данными: их
   высоты и сроки действия нужно подтвердить отдельно.
3. Кнопками «Взлёт», «Посадка» и «Резерв» выберите роль точки, затем нажмите
   нужное место на карте. Добавьте несколько площадок, если это требуется;
   в списке каждой точки можно назначить конкретный БВС или весь парк.
4. Проверьте тип работ, высоту и параметры сенсора. Боковое и продольное
   перекрытие, GSD и ширина полосы влияют на галсы. Тип работ должен входить
   в задачи установленной полезной нагрузки хотя бы одного включённого БВС.
5. Проверьте паспортные и эксплуатационные поля парка: скорость, время полёта,
   ветер, заряд, состояние АКБ, резерв, высотные пределы и назначенные площадки.
   Значения по умолчанию не подтверждают конфигурацию конкретного борта.

## Расчёт и проверка

Выберите «Срок работ» для минимизации календарной длительности или «Суммарный
налёт» для минимизации времени в воздухе по всему парку. «Баланс» ищет минимум
налёта при заданном сроке. Поля «Срок, мин» и «Макс. БВС» ограничивают задачу;
пустые поля не вводят ограничений. Простая эвристика выключена по умолчанию.

Укажите ветер, необходимые временные окна и, если известен, минимальный радиус
разворота. Ноль метров отключает ограничение радиуса. Положительное значение
применяется к горизонтальному маршруту, включая транзит к съёмке и подход к
посадке. Оно не подтверждает разбег, глиссаду или вертикальную динамику.

Нажмите закреплённую кнопку «Рассчитать план». После расчёта проверьте:

- статус выполнимости и причины отказа, если план не построен;
- рабочие и запретные зоны, галсы и перелёты на карте;
- срок, суммарный налёт и долю полезного пути;
- список задействованных БВС и время каждого вылета;
- независимый аудит ограничений и перечисленные в ответе API допущения.

После любого изменения сценария прежний план сбрасывается: рассчитайте его
заново. Для каждого задействованного БВС выберите карточку миссии и скачайте
KML или GeoJSON. Дополнительно доступны QGroundControl `.plan` и Mission Planner
`.waypoints`. Импортируйте файл в фактически применяемую версию целевого ПО и
проверьте высоты, команды камеры, старт, посадку и все точки маршрута до полёта.

## Три короткие проверки перед демонстрацией

1. «Городская ортофотосъёмка»: рассчитайте минимум срока, затем минимум налёта.
   Первый критерий может привлечь больше БВС, второй может увеличить срок.
2. «Несколько городских кварталов»: покажите три раздельные рабочие области,
   четыре запретные зоны и маршруты, проходящие независимый аудит.
3. «LiDAR-коридор»: с исходным парком покажите безопасный отказ из-за отсутствия
   подтверждённой LiDAR-нагрузки. Для положительного расчёта нужен профиль БВС
   с реально установленным совместимым сенсором.

Описание форматов API и команд проверок находится в [README](../README.md).
Методика масштабного теста и ограничения перечислены в
[аудите соответствия требованиям](final-requirements-audit-20260928.md).
