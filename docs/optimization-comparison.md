# Сравнение алгоритмов оптимизации GeoPlan

Дата измерения: 23 сентября 2026 года. Бенчмарк воспроизводится командой:

```powershell
cd backend
uv run python -m benchmarks.compare_optimizers
```

## Методика

Одинаковый набор из девяти участков распределяется между тремя БВС с разными
крейсерскими скоростями и временем транзита. Основная метрика — время завершения
всего объёма работ, дополнительная — суммарный налёт. Точный перебор
используется только как нижняя контрольная точка для небольшого сценария.

Время исполнения — медиана семи локальных прогонов после прогрева. Оно предназначено
для оценки порядка величины; абсолютное значение зависит от компьютера.

## Вывод

Интерактивный расчёт состоит из следующих этапов:

1. Boustrophedon/sweep формирует галсы внутри целевого полигона.
   Для каждого пакета галсов строятся варианты входа слева и справа; вместе с
   реверсом это даёт до четырёх допустимых пар начала и конца съёмки.
2. Граф видимости строит кратчайшие безопасные переходы между точками вокруг
   объединённых запретных зон с буфером безопасности.
3. Для каждого участка полностью сравниваются допустимые комбинации точки старта,
   варианта змейки, прямого или обратного обхода галсов и точки посадки. Стоимость
   считается по безопасному пути, а не по расстоянию по прямой.
4. Рабочий решатель использует точный метод ветвей и границ, при числе БВС не более 6 и пространстве
   назначений не более 2 000 000 комбинаций. Количество участков само по себе
   не переводит задачу в эвристический режим.
5. Для более крупных задач LPT формирует начальное назначение, которое затем
   улучшается локальным поиском.

Статус `proven_optimal` относится к распределению БВС по уже сгенерированным
безопасным маршрутам. Он не объявляет Boustrophedon-маршрут глобально кратчайшим
среди всех возможных геометрий покрытия; область доказательства явно возвращается
в поле `optimization.scope` API.

В ответе API отдельно возвращаются `survey_distance_km`, `transit_distance_km`
и `useful_flight_percent`. Это позволяет контролировать долю пути, на которой
БВС действительно выполняет съёмку, и не скрывать перелёты к рабочей зоне и обратно.

Генетический алгоритм показал лучшее приближение среди ограниченных по времени
метаэвристик, но требует примерно в тысячу раз больше времени, чем LPT на этом
малом тесте. Его имеет смысл добавить как отдельный режим с увеличенным бюджетом вычислений для
крупных сценариев. Точный метод ветвей и границ подходит для малых задач и проверки
качества, но экспоненциально растёт с числом участков.

## Рассмотренные семейства и применимость

1. **Round robin** — полезная базовая линия, не учитывает характеристики БВС.
2. **Fastest platform** — минимизирует часть индивидуальных полётов, но теряет
   параллелизм.
3. **Cheapest individual** — хороший ориентир для критерия суммарного налёта.
4. **Least loaded greedy** — быстрый онлайн-вариант при поступлении новых работ.
5. **LPT + локальный поиск** — текущий интерактивный режим для крупных задач.
6. **Regret insertion** — полезен при сильно неоднородной совместимости БВС.
7. **Локальный поиск** — недорого улучшает готовое жадное решение.
8. **Simulated annealing** — способен выходить из локальных минимумов, но требует
   настройки температуры и бюджета итераций.
9. **Genetic algorithm / NSGA-II** — перспективен для двухкритериальной
   оптимизации и построения фронта Парето.
10. **Точный метод ветвей и границ** — рабочий режим для небольших сценариев;
    CP-SAT/MILP остаются следующим вариантом для более богатой временной модели.

## Научная и техническая основа

- Boustrophedon cellular decomposition является полным методом покрытия области:
  [Choset & Pignon, Carnegie Mellon University](https://publications.ri.cmu.edu/coverage-path-planning-the-boustrophedon-decomposition).
- Кратчайший путь среди полигональных препятствий можно искать по графу видимости:
  [University of Maryland, Shortest Paths and Visibility Graphs](https://www.cs.umd.edu/class/spring2020/cmsc754/Lects/cmsc754-spring2020-lects.pdf).
- A* даёт формальную основу оптимального эвристического поиска по графу:
  [Hart, Nilsson & Raphael](https://ai.stanford.edu/~nilsson/OnlinePubs-Nils/PublishedPapers/astar.pdf).
- Для будущей точной модели распределения БВС подходят VRP, CP-SAT и MILP:
  [официальная документация OR-Tools](https://developers.google.com/optimization/routing),
  [MIP](https://developers.google.com/optimization/mip).
- Имитация отжига применима к дискретным пространствам с локальными минимумами:
  [Bertsimas & Tsitsiklis](https://www.mit.edu/~dbertsim/papers/Optimization/Simulated%20annealing.pdf).
- NSGA-II предназначен для эффективного многокритериального поиска:
  [Deb et al.](https://ieeexplore.ieee.org/document/996017).
- Ant Colony System является альтернативой для задач типа TSP/VRP:
  [Dorigo & Gambardella](https://ieeexplore.ieee.org/document/585892).
- RRT* остаётся перспективным для динамических или неполностью известных
  пространств, но для статических 2D-полигонов граф видимости проще и точнее:
  [Karaman & Frazzoli](https://roboticsproceedings.org/rss06/p34.pdf).

Полные числовые результаты находятся в `docs/optimization-comparison.csv`.
