# Приёмка и ограничения эксплуатации

Контрольные результаты, параметры и хеши исходников сохранены в
[сводке масштабной приёмки](../reference/benchmarks/service-acceptance-2026-10-19.json).
Каждый запуск относится к указанной в нём версии. Его время и результат
не переносятся автоматически на последующие версии сервиса.

Проверены HTTP-расчёт, независимый аудит, модель кадров и экспорт. Лётная
приёмка, калибровка энергопотребления и проверка конкретных прошивок не выполнены.
В масштабной серии выявлены ограничения пакетного покрытия и ресурсного
назначения; они не считаются закрытыми без повторного прогона.

## Воспроизведение

Запускайте отдельный тестовый сервис с собственным хранилищем проектов.
Команды выполняются из корня репозитория:

```powershell
uv run --directory backend --locked --extra optimization python -u -m benchmarks.service_acceptance quality --url http://127.0.0.1:8002 --container YOUR_TEST_CONTAINER --output ../work/acceptance-quality.jsonl --budget 1800 --stream
uv run --directory backend --locked --extra optimization python -u -m benchmarks.service_acceptance load --url http://127.0.0.1:8002 --container YOUR_TEST_CONTAINER --output ../work/acceptance-load.jsonl --budget 60 --users 2 4 8
```

Драйвер сохраняет запросы, сжатые ответы, параметры и хеши кода; проверяет
аудит, кадры, GIS-экспорт и отдельные задания автопилотов. `--names` выбирает
сценарии, `--counts` без чисел отключает пакеты исходных полигонов.

Контрольная серия выполнялась в Docker с 16 CPU и 31,27 GiB памяти без
лимитов контейнера. Парк, камеры, площадки, ветер и DEM синтетические.
В пакетах из [исходного KML](source-data.md) реальны только контуры.

## Масштабные сценарии

| Сценарий | Бюджет / время расчёта | Результат контрольного запуска |
|---|---|---|
| 100 км², 10 БВС, `balanced`, срок 180 мин | 270 с / 12,93 с | Аудит пройден; 14 вылетов, завершение за 179,90 мин |
| 100 км², минимум срока | 270 с / 14,52 с | Аудит пройден; 18 вылетов, завершение за 126,53 мин |
| 100 км², минимум налёта, дополнительно задан срок 180 мин | 270 с / 4,15 с | Аудит пройден, но срок 863,27 мин: ограничение нарушено, автопилотный экспорт отклонён |
| 100 км², минимум налёта без ограничения срока | 1800 с / 4,30 с | Первый план за 0,49 с; аудит и четыре формата экспорта пройдены |
| 100 км², запреты, препятствия, ветер | 270 с / 91,09 с | Аудит пройден; 112 вылетов, завершение за 412,12 мин |
| 100 км², DEM/AGL, ветер и временное окно | 270 с / 270 с | Бюджет исчерпан до первого проверенного плана |
| Тот же DEM-сценарий с увеличенным бюджетом | 1800 с / 462,08 с | Первый план за 285,35 с; завершение работ за 464,90 мин; аудит и 40 экспортов пройдены |
| 32 / 64 / 128 исходных полигонов | 270 с / 64,04 / 74,56 / 100,63 с | `coverage_generation_failed` для `zone-316-2` |

На трёх плоских сценариях проверены 46 287 кадров и 100% модельного покрытия.
На сценарии с ограничениями — 78 856 кадров, на DEM — 82 513 кадров;
в обоих случаях покрытие 100%, статус качества `partial` из-за допущений модели.
Этот статус не означает полную фотограмметрическую проверку.

Три размера пакетов содержат один проблемный контур: это повторения одного
дефекта, а не три независимых класса ошибок. Проверка одиночного `zone-316`
его не воспроизвела. Ошибка проявляется в контексте пакетного покрытия;
небезопасный план вместо отказа не выдаётся.

DEM проверялся до и после добавления контроля бюджета между кандидатами.
В предшествующем запуске получены 517,00 с полного расчёта и 298,73 с до
первого плана. Эти единичные измерения не доказывают устойчивого ускорения.
Начальная стадия в повторе заняла 30,02 с; кооперативные лимиты не прерывают
отдельный длительный нативный вызов.

## Конечный ресурс парка

| Условия на 100 км² | Результат |
|---|---|
| Два комплекта АКБ на БВС | После исправления внутреннего сбоя возвращается `unplannable_segment`; допустимое решение при этом существует |
| Четыре комплекта АКБ, остаток ТО — пять вылетов и семь часов | Первый план за 1,56 с, итог за 20,44 с; 18 вылетов; аудит, кадры и четыре формата проверены |

План второго запуска фактически использует один или два комплекта на борт.
Его маршруты и расписание прошли повторный аудит с исходным ограничением
в два комплекта и более строгим ТО. Это подтверждает существование допустимого плана:
отказ первого запуска вызван недостатком эвристического поиска, а не доказанной
нехваткой ресурса. Данные проверки сохранены в контрольной сводке.

## Нагрузка и отмена

| Одновременные запросы | Принято / HTTP 503 | Время принятых запросов | Health p95 |
|---:|---:|---:|---:|
| 2 | 2 / 0 | 28,83–28,89 с | 0,115 с |
| 4 | 2 / 2 | около 35,6 с | 0,152 с |
| 8 | 2 / 6 | около 32,7 с | 0,132 с |

В одном процессе допускаются два расчёта, очереди нет. Остальные запросы
получают HTTP 503 и могут быть повторены. Это проверка контролируемой перегрузки,
а не возможность вести восемь расчётов параллельно.

Аудит принятых планов пройден, отпечатки входных данных совпали; смешения
результатов клиентов не обнаружено. После разрыва потока слоты освобождались
примерно за 1,35–1,42 с. Выборочно измеренный пик памяти контейнера — 153,8 MiB.
Неуспешные подключения во время старта контейнера сохранены в сводке отдельно
и не включены в таблицу. Нагрузочный бюджет 60 с не проверяет длительную
работу нескольких получасовых заданий.

## Условия эксплуатационной приёмки

Матрица требований и реализаций находится в [requirements.md](requirements.md).
До полевого применения необходимо:

- исправить пакетное покрытие и повторить 32/64/128 областей;
- устранить пропуск допустимого назначения при конечном ресурсе АКБ;
- проверить крупный неоднородный парк с реальными площадками и ограничениями;
- согласовать постоянную высоту съёмки AGL с вертикальным разведением миссий;
- подтвердить профили БВС, камер, резервов и регламентов ТО;
- проверить задания в целевых версиях полётного ПО и на оборудовании;
- выбрать схему очереди и ресурсы сервера для требуемой нагрузки.

Автоматические проверки и ручные сквозные сценарии перед объединением и
выпуском перечислены в [чек-листе](release-checklist.md).
