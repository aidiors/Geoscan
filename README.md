# GeoPlan

GeoPlan — веб-сервис подготовки индивидуальных полётных заданий для группы БВС.
Он принимает область работ, характеристики аппаратов, ветер, разрешённое
воздушное пространство, запретные зоны, высотные препятствия и площадки посадки.
Результат содержит маршруты, расписание вылетов и оценку выполнимости. Задания
можно скачать в KML, GeoJSON, QGroundControl `.plan` и Mission Planner `.waypoints`.

## Возможности

- Три критерия: минимальный срок работ, минимальный суммарный налёт и минимальный
  налёт при заданном сроке. Можно ограничить число привлекаемых БВС.
- Построение галсов для полигонов с отверстиями и нескольких рабочих областей.
  Для сложной геометрии сравниваются варианты с разными направлениями галсов.
- Расчёт шага галсов, интервала съёмки и допустимой скорости по сенсору, высоте,
  GSD и перекрытию. Поддерживаются типы задач RGB, мультиспектральная, ИК, LiDAR,
  геофизическая и видеосъёмка; совместимость нагрузки проверяется до расчёта.
  Для LiDAR, геофизики и видео отдельные физические модели съёмки не реализованы.
- Обход запретных зон и высотных препятствий с заданным отступом; проверка
  маршрута по разрешённому пространству и временным окнам.
- Учёт встречного, попутного и бокового ветра, скорости съёмки и транзита,
  состояния АКБ и обязательного резерва.
- Несколько площадок взлёта, посадки и резерва с привязкой к БВС. Достижимость
  аварийной площадки проверяется на всём маршруте с учётом остатка энергии.
- Расписание повторных вылетов с подготовкой, ожиданием открытия воздушного
  пространства и сдвигом конфликтующих миссий. При разведении учитываются
  заданные допуски положения, скорости и времени старта.
- Высотные ограничения AGL/MSL и профиль рельефа по DEM, в том числе GeoTIFF.
  Можно включить разведение конфликтующих маршрутов по высоте.
- Независимый аудит плана: 12 проверок геометрии, высот, временных ограничений,
  расписания, дистанции между БВС, АКБ, аварийного ухода, покрытия и экспортов.
- Импорт KML и GeoJSON: Polygon, внутренние контуры, LineString, Point, высоты,
  `altitudeMode` и `ExtendedData`.
- Экспорт команд взлёта, скорости, включения и выключения триггера камеры и
  посадки для QGroundControl и Mission Planner.
- Карта OpenStreetMap, редактор парка, демонстрационные сценарии, сохранение
  настроек в браузере и прогноз технического обслуживания по полётам или налёту.

## Алгоритм планирования

1. Построить галсы внутри рабочей области. Автоматический выбор направления
   учитывает геометрию, а при ветре — расчётное время полного маршрута для
   медианной крейсерской скорости допустимого парка.
2. Сравнить глобальное покрытие с декомпозицией на секции. Деление принимается
   при улучшении стоимости с учётом перелётов к площадкам.
3. Для каждого участка и БВС построить допустимые варианты входа, направления
   обхода, старта и посадки. Проверить полезную нагрузку, ветер, ограничения
   пространства и запас АКБ; учесть съёмку и транзит раздельно.
4. Распределить участки. По умолчанию точный метод ветвей и границ применяется
   при числе БВС не более 6 и пространстве назначений не более 2 000 000
   комбинаций. Для более крупных задач используются эвристики и локальный поиск.
5. Составить расписание, учесть временные окна и устранить опасные сближения.
6. Повторно проверить итоговый план независимым аудитом и подготовить экспорт.
7. При `productive_routing=true` сравнить проверенные группы вылетов и ограниченный
   пул свободных контуров/дуг с прямым центром. Свободный вариант принимается
   после расписания и аудита, если не ухудшает налёт, подлёт, возврат и camera-off.
   В интерфейсе этот поиск включён; свободная геометрия пока доступна для одной
   плоской RGB-области. [Границы и устройство](docs/architecture/README.md#свободное-покрытие).


Режим по умолчанию — `optimized`. Быстрая жадная эвристика включается отдельно.
Статус `proven_optimal` относится к распределению по построенным вариантам
маршрутов. Он не доказывает глобальную оптимальность геометрии или расписания.
Контракт распределения `AssignmentOptimizer` позволяет заменить решатель без
изменения HTTP API.

Минимальный радиус разворота задаёт пользователь: в исходных характеристиках
БВС его нет. Значение 0 м отключает ограничение кривизны; положительный радиус
применяется к переходам между генерируемыми галсами, транзиту к съёмке и подходу
к посадке. Если допустимый переход не найден, расчёт завершается ошибкой.
Проверка горизонтального маршрута не подтверждает разбег, глиссаду и вертикальную
динамику взлёта и посадки. Отдельный анализ радиуса описан в
[допущениях о манёвренности](docs/maneuverability-assumptions.md).

## Запуск

Требуются Python 3.14, `uv` и Node.js 22.13.0 или новее.

Python 3.14 закреплён в `backend/.python-version`, метаданных проекта и CI.
Следующая минорная версия Python подключается после отдельной проверки
совместимости зависимостей.

```powershell
npm ci
npm run build
cd backend
uv sync --locked
uv run uvicorn geoplan.bootstrap:app --host 127.0.0.1 --port 8000
```

Интерфейс и API: `http://127.0.0.1:8000/`.
Документация OpenAPI: `http://127.0.0.1:8000/docs`.
Работа со сценарием и экспортом описана в
[руководстве оператора](docs/operator-guide.md).

### Docker

Требуется Docker Desktop или Docker Engine с Compose. Из корня проекта:

```powershell
docker compose up --build
```

Интерфейс доступен по адресу `http://127.0.0.1:8000/`. Для другого порта:

```powershell
$env:GEOPLAN_PORT=8080
docker compose up --build
```

Контейнер собирает интерфейс, запускает FastAPI от непривилегированного
пользователя и проверяет `/health`. Остановка:

```powershell
docker compose down
```

### Демонстрационные сценарии

Кнопка **«Демо-кейсы»** открывает готовые сценарии. В карточке указаны задача,
параметры и ожидаемый результат; сценарий можно загрузить и сразу рассчитать.
Примеры показывают обход препятствий, влияние ветра, разные типы работ,
распределение между БВС, минимизацию налёта и отказ при недопустимом ветре.

## Проверки

Из корня проекта:

```powershell
npm ci
npm run typecheck
npm run lint
npm run check:architecture
npm test
npm run build
npm run test:e2e
```

Из каталога `backend/`:

```powershell
uv sync --locked
uv run ruff format --check .
uv run ruff check .
uv run ty check src tests benchmarks scenarios
uv run pytest -q
uv run python -m benchmarks.compare_optimizers
```

Зависимости сервера включают устанавливаемый пакет `geoplan`. После изменения
`pyproject.toml` выполните `uv sync --locked` повторно. Серверные тесты работают
без сборки интерфейса. Проверка структуры из корня проекта:

```powershell
python scripts/check_architecture.py
python scripts/check_docs.py
```

HTTP-контракт можно выгрузить без запуска сервера и без `dist/`:

```powershell
uv run --directory backend python ../scripts/export_openapi.py --output ../work/openapi.json
```

Сквозная проверка поднимает приложение на порту `8013` и использует установленный
Google Chrome. Перед ней установите зависимости обеих частей проекта.
Команды воспроизведения и ограничения интерпретации результатов приведены в
[инструкции бенчмарков](docs/benchmarks.md).

## API

| Метод и путь | Назначение |
|---|---|
| `GET /health` | состояние сервиса |
| `POST /v1/plans` | построение плана |
| `POST /v1/imports/kml` | импорт KML до 25 млн символов |
| `POST /v1/imports/geojson` | импорт GeoJSON |
| `POST /v1/turn-radius-analysis` | анализ предполагаемого радиуса разворота |
| `POST /v1/exports/kml` | экспорт миссии в KML |
| `POST /v1/exports/geojson` | экспорт миссии в GeoJSON |
| `POST /v1/exports/qgroundcontrol` | экспорт QGroundControl |
| `POST /v1/exports/mission-planner` | экспорт Mission Planner |

Числовые диапазоны высот требуют явной системы отсчёта AGL или MSL. При полёте
по рельефу профиль содержит обе величины; каждый слой проверяется в своей
системе отсчёта. FL требует предварительного преобразования в MSL с учётом QNH.
Формат полей описан в [контракте 4D-ограничений](docs/4d-geodata-contract.md).

## Структура проекта

| Каталог или модуль | Назначение |
|---|---|
| `backend/src/geoplan/bootstrap.py`, `composition.py` | точка запуска и сборка зависимостей |
| `backend/src/geoplan/api/` | HTTP-маршруты и создание приложения |
| `backend/src/geoplan/domain/` | координаты, парк, миссии, ограничения и диагностика |
| `backend/src/geoplan/planning/` | этапы планирования, кандидаты, ограничения и отчёты |
| `backend/src/geoplan/coverage/` | галсы, оценка вариантов и декомпозиция зон |
| `backend/src/geoplan/navigation/` | геометрия, обход ограничений, Dubins и Hybrid A* |
| `backend/src/geoplan/assignment/`, `scheduling/` | распределение и расписание |
| `backend/src/geoplan/airspace/`, `flight/` | временные окна, рельеф, энергия и аварийный уход |
| `backend/src/geoplan/safety/`, `geodata/` | независимый аудит, импорт и экспорт |
| `backend/benchmarks/` | вычислительные эксперименты |
| `backend/scenarios/` | общие фабрики данных для тестов и экспериментов |
| `backend/tests/{unit,integration,contracts,benchmarks}/` | серверные проверки по назначению |
| `frontend/src/app/` | сборка экрана и тема |
| `frontend/src/features/` | планирование, демонстрации, импорт и экспорт |
| `frontend/src/widgets/`, `shared/` | карта, HTTP-транспорт и общая геометрия |
| `frontend/e2e/` | сквозные проверки интерфейса |
| `dist/` | локальная сборка Vite; создаётся командой build, исключена из Git |
| `reference/` | исходные материалы кейса |

Внутренние модели алгоритмов находятся рядом с их реализацией в `models.py`.
Правила зависимостей и описание рефакторинга — в
[документации архитектуры](docs/architecture/README.md).
